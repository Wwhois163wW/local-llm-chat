# core/session.md

## 1. 技术设计要点/总结
*   **核心组件**: `ChatSession` 类是此模块的核心, 封装了与LLM单次会话的所有状态和逻辑。
*   **API优先设计**: `ChatSession` 作为一个独立、可复用的模块, 不处理具体的输入/输出, 只负责接收字符串、管理历史和返回结果。这使得它可以被轻松集成到不同的应用中 (如CLI, GUI)。
*   **状态管理**: `ChatSession` 实例内部维护一个 `history` 列表, 存储当前会话的完整上下文。
*   **上下文控制**:
    *   为了防止上下文无限增长导致的性能问题或token溢出, `ChatSession` 实现了一个**滑动窗口**机制。
    *   窗口大小由 `config.ini` 中的 `max_history_length` 参数控制。
    *   每次发送新消息前, 模块会自动检查历史记录长度, 如超出限制, 则会从开头裁剪掉最旧的消息。
*   **错误处理**: `send_message` 方法内置了 `try-except` 块, 在API调用失败时会记录错误并返回 `None`, 同时确保历史记录不会被破坏。
*   **数据统计**: `send_message` 现在会在 API 调用前后记录时间, 并从 API 返回的 `usage` 字段中提取 token 使用量。这些数据作为元组的一部分与回复内容一起返回。
*   **文件内容注入**: 增强后的 `send_message` 方法现在接受一个 `files` 参数（文件路径列表）。它会负责读取这些文件的内容，使用默认的 Prompt 模板进行包装，并将其作为上下文消息注入到对话历史中，然后连同用户的原始提问一起发送给 LLM。这种注入是“静默”的，即在文件内容注入阶段不会单独触发 API 调用，所有内容都在一次请求中提交。
*   **错误处理与反馈**: 在文件注入过程中，增加了对文件路径有效性和文件大小的检查（大小限制可在 `config.ini` 中配置）。所有非致命错误（如文件未找到、文件过大）会被收集并存储在 `session.last_errors` 列表中，供调用方（如 `main.py`）获取并展示给用户。
*   **流式事件生产者 (Streaming Event Producer)**: 作为项目架构升级的一部分，`send_message` 方法已被重构为一个**生成器**。它使用 `stream=True` 模式调用 API，并 `yield` 一系列事件对象（如 `TextChunk`, `StatsUpdate`），而不是一次性返回完整结果。这使得调用方可以实现实时的“打字机”效果。
*   **客户端 Token 统计**: 为了解决流式模式下 API 不返回 `usage` 字段的问题，本项目集成了 `tiktoken` 库。`send_message` 方法现在会在客户端手动计算 `prompt_tokens` 和 `completion_tokens`，从而提供准确的 Token 使用统计。
